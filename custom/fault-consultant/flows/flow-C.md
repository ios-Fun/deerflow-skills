# C类：异常演变分析

## 前置条件
- **不需要诊断单**，直接执行本流程
- 所有内容必须围绕用户输入的测点或特征，不允许查询任何无关内容

## 执行步骤

1. **获取诊断单**
   - 根据 `user_enrichment` 内的 `type` 字段，按`schemas/tool-routing.md`内的规则查询对应诊断单列表
   - 如果没有获取到任何诊断单：说明当前用户提问的情况不符合任何故障模式，直接告知用户

2. **获取推导图**
   - 拣取诊断单内故障名称
   - 调用 `default_graph_detail` 获取推导图，列出候选模式

3. **筛选故障模式**
   - 筛选出与当前测点相关的故障模式
   - 选择出与当前情况最可能相关的故障模式
   - **最终只定位到一个故障模式**
   - 输出：【已满足特征】【缺失/未满足特征】【不支持证据】
   - 结论句："最可能 + 其他可能性 + 诊断依据 + 风险 + 建议检查项"

4. **分析测点数据**
   - 在该故障模式下检索出当前给定测点所在链路
   - 调用 `get_tag_statistic_data` 获取用户输入测点数据
   - 分析该点数据的变化在该故障模式中的影响
   - **务必只分析该点的变化情况，不要涉及其他测点**

5. **接口调用失败处理**
   - 不要换角度处理
   - 直接告知用户该链路不可通
   - 之后查阅别的链路

6. **时间轴还原**
   - 按时间轴还原：首个偏离参数 → 扩散参数 → 诊断触发 → 当前状态
   - 明确时间先后（如"13:48 油温 → 14:05 轴承温度 → 14:26 振动"）
   - 给时间差

7. **因果推断**
   - 强调"基于现有数据的推断"
   - 证据不足则说"暂不能确定因果，只能确认时间相关"

8. **生成演化图**
   - 需要时生成带时间戳的故障演化图（Mermaid Gantt）

## 回答要求

1. **不得**为了验证目标测点实际值而无条件查询其他测点
2. 若用户要求确认某故障，明确回答：**可确认 / 疑似 / 证据不足**
3. **只允许**查询目标设备本身及其直接挂载测点，禁止任何跨设备查询

## 输出格式

### 结论
- 直接回答演变过程

### 证据
- 时间轴（按时间先后排列）
- 各时间点的参数变化

### 分级与风险
- 当前状态评估

### 建议动作
- 基于演变趋势的建议

### 边界说明
- 哪些是数据支持的、哪些是推断的

### 附录
- 输出【故障推导图】，内容格式读取 `schemas/fault-analysis.md` 下对应的渲染协议
- 输出【故障演化图】（Mermaid Gantt格式）
