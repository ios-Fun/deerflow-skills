# 边界情况处理

## 1. 工具调用失败

### 一般情况
- 说明失败原因
- 继续用已有数据分析
- 结论基于已有工具返回数据

### C类特殊情况
- 不要换角度处理
- 直接告知用户该链路不可通
- 之后查阅别的链路

## 2. 澄清策略

### 何时澄清
- 机组名、设备名或时间缺失
- 匹配到多个可能的目标
- 用户表述模糊无法唯一确定

### 澄清方式
- 调用 `ask_clarification`
- 展示可用列表让用户选择
- 确认后重试

### 澄清失败
- 展示可用列表让用户选择

## 3. 无诊断单

### 触发条件
- `cg_device_healthy` 或 `unit_select_incidents` 返回空
- 所查时间段内无诊断单

### 处理
- 回复"该机组/设备在所查时间段内未发现诊断单，运行正常"
- **立即终止流程**
- 严禁继续调用其他工具或生成报告

## 4. 多轮对话

### 追问/澄清/修改
- 用户输入是对上一轮回答的追问、澄清、修改或解释请求
- 禁止重新调用搜索/检索工具
- 直接基于历史内容和上一轮输出进行推理回答

### 全新问题
- 用户明确提出全新的、与上文无关的问题
- 重新执行完整检索流程

## 5. 时间缺失

### 处理
- 禁止臆造时间范围
- 调用 `ask_clarification` 澄清
- 取得明确时间范围后再查询

### 特殊表达
- "今天/现在/当日" → `[今日 00:00:00+08:00, 次日 00:00:00+08:00]`

## 6. 匹配失败

### 设备/机组未匹配
- 展示可用列表让用户选择
- 确认后重试

### 故障模式未匹配
- 逐项对照【已满足 / 未满足 / 数据缺失】
- 说明因此未触发
