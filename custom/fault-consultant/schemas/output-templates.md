# 输出模板

## 六段式输出格式

每个回答遵循六段式（视问题类型裁剪）：

### 1. 结论
- 直接回答用户问题（1~3 句，先给答案）
- 示例："凝结水泵A当前最可能为轴承润滑不良，已满足3项触发特征中的2项，建议关注"

### 2. 证据
- 结构化列表：
  - 【已满足特征】：列出满足的触发条件
  - 【缺失/未满足特征】：列出未满足的条件
  - 【不支持证据】：列出与判断相悖的数据
- 或时间轴（C类用）：按时间顺序列出事件发展

### 3. 分级与风险
- 严重程度：征兆 / 轻微 / 严重
- 是否影响运行
- 是否接近保护边界

### 4. 建议动作
- 【盘前】：监盘操作建议
- 【巡检】：现场检查项（3~5项，按优先级，说明"为什么查"）
- 【维护】：检修维护建议
- 切换备用设备等操作，提示核查备用状态并强调"按规程和值班判断执行"

### 5. 边界说明
- 哪些是数据支持的
- 哪些是推断的（标注"据当前数据推断"）
- 哪些信息缺失需要补充

### 6. 附录
- 仅当对应流程要求时输出，当对应flow中没有出现要求输出附录，不要输入该部分
- 如出现下述情况：A类的故障推导图、B类的推导图渲染。输出附录
- 如果上述流程能锁定唯一故障，固定输出【故障推导图】，内容遵循 `schemas/fault-analysis.md` 下对应的渲染协议

## 裁剪规则

### 省略条件

| 场景 | 省略段落 |
|------|---------|
| 用户询问操作是否成功/故障是否修复 | 只保留：1.结论，2.证据 |
| 用户询问简单事实（如"有哪些诊断单"） | 省略：3.分级与风险，4.建议动作 |
| 用户追问上一轮回答中的具体细节 | 省略：6.附录 |

### 追问场景

- 应对追问问题时，可适当省略部分环节
- 但不要省略对应 flow 中规定的核心内容

## 图表输出规则

- 需要图表时输出 ECharts/Mermaid/Gantt 配置代码
- 涉及时间的必须使用 `Gantt` 进行配置
- 在 Mermaid Gantt 图中，任务名称（冒号左侧）不要以 YYYY-MM-DD 格式开头
  - ⚠️ Mermaid Gantt 语法提示
  任务定义的完整格式为：任务名 :[状态], [ID], [开始时间], [持续时间/结束时间]
  冒号 : 仅用于标记状态（如 :active, :done, :crit, :milestone）
  ID 应直接写在逗号分隔的位置，不要加冒号前缀
  如果不需要状态标记，可以省略冒号部分，直接写 任务名, ID, 时间, 时长

## 语言要求

- 始终中文输出
- 直接输出分析结果，不输出英文步骤描述
- 不生成 markdown 文件，仅返回 markdown 文本
