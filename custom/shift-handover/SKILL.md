# 交接班分析

## 前置规则
进入本 Skill 后，首先读取 `duty-roster.md`。
根据 `duty-roster.md` 中定义的值班规则，结合当前时间判断：
- 当前处于哪个值次
- 当前值班开始时间
- 当前值班结束时间
- 上一值的开始时间和结束时间

后续涉及“上个值”“上一班”“本班”等相对时间描述时，统一以该值班规则判断结果为准。
不得自行假设固定的白班、夜班时间，也不得直接按照自然日划分班次。
如果当前时间无法根据 `duty-roster.md` 唯一确定值次，应停止后续交接班分析，并说明无法确定当前值次。

## 分析范围

根据用户问题决定需要查询的数据范围，不要求每次调用全部接口。

## 上一班重要事项

用户询问：上个值上班期间发生了哪些重要的事情？ 查询上一值时间范围内的异常、报警：
- 调用`unit_select_incidents`查询在上个值时间范围内发生的诊断单数据，closed参数设为null
- 调用`unit_alarm_list_statistics`查询上个值时间范围内发生的报警单统计数据

重点识别重大异常、重要报警及其他具有交接价值的事件。
注：若接口返回数据为空，直接回复用户，禁止扩大范围进行查询。

## 上一班完成工作

用户询问： 上个班组做了哪些工作？ 查询上一值时间范围内的工作记录和定期工作：
- 调用`unit_select_incidents`查询在上个值时间范围内发生的诊断单数据，closed参数设为true
- 调用`unit_alarm_list_statistics`查询上个值时间范围内发生的报警单统计数据, closed参数设为true

注：若接口返回数据为空，直接回复用户，禁止扩大范围进行查询。

## 重点关注事项

用户询问：哪些事情需要加强关注？ 查询上一值发生的异常及当前仍存在的问题：
- 调用`unit_select_incidents`查询在上个值时间范围内发生的诊断单数据，closed参数设为false
- 调用`get_alarm_list`查询上个值时间范围内发生的报警单数据, closed参数设为false
- 调用`unit_alarm_list_statistics`查询上个值时间范围内发生的报警单统计数据, closed参数设为false 

重点识别尚未消除的异常、未关闭报警、需要持续监视或后续确认的事项
注：若接口返回数据为空，直接回复用户，禁止扩大范围进行查询。

## 本班继续完成工作
用户询问：我们值上班需要继续完成哪些工作？
- 调用`unit_select_incidents`查询在目前值时间范围内发生的诊断单数据，closed参数设为false
- 调用`get_alarm_list`查询目前值时间范围内发生的报警单数据, closed参数设为false
- 调用`unit_alarm_list_statistics`查询目前值时间范围内发生的报警单统计数据, closed参数设为false

识别目前仍存在的未关闭的以及需要继续处理的工作。
注：若接口返回数据为空，直接回复用户，禁止扩大范围进行查询。

# 完整交接班

用户要求：生成交接班清单或者要求综合分析上一值情况时，在确定当前值次和上一值时间范围后，根据需要综合查询：
根据“本班继续完成工作”来分析：
- 根据诊断单查询设备缺陷情况：统计查询到的诊断单id
  - 调用 `unit_mount_path` 获取基于机组的设备层级路径。
  - 调用 `unit_graph_show` 获取故障知识图谱。
  - 调用 `unit_tags_realtime` 获取诊断单生成时关联运行参数前后半小时内统计数据。
- 异常测点趋势变化
  - 根据`get_alarm_list`的测点报警单中的tagId调用`get_tag_statistic_data`获取测点统计数据
对不同接口返回的同一事项进行关联和合并，避免同一问题重复交接。

## 交接事项分析

每个需要交接的事项重点判断：
* 发生了什么
* 什么时候发生
* 当前状态
* 是否已经处理完成
* 是否需要继续关注
* 本值需要继续做什么

对于异常测点参数，重点判断异常是否仍然存在以及变化趋势。
对于设备缺陷，重点判断当前缺陷状态和后续处理要求。
对于未完成工作，重点明确当前进度以及下一步工作。
不得根据缺失的数据推测处理结果、完成状态或后续要求。

## 输出格式

完整交接班清单按以下结构输出：

### 1. 上一值重要事项

上一值期间发生的重要事件、异常、报警及运行操作。

### 2. 上一值完成工作

上一值已经完成的主要工作及处理结果。

### 3. 重点关注事项

当前仍存在、需要本值重点监视或跟踪的问题。

### 4. 本值继续完成工作

上一值未完成、需要继续处理、验证、确认或跟踪的工作。

### 5. 其他交接事项

仅在存在其他具有交接价值的信息时输出。

## 调用原则

不要机械调用全部接口。

根据用户实际问题确定查询范围：

* “上个值发生了什么” → 事件、异常、报警、日志
* “上个值做了什么” → 工作记录、定期工作
* “哪些需要关注” → 异常、缺陷、参数、未闭环事项
* “本值需要做什么” → 未完成工作、定期工作、缺陷后续处理
* “生成完整交接班” → 综合查询相关信息

完成当前问题所需的信息获取后立即停止调用，不继续查询无关数据。
