description: >
  面向火电机组集控值班员、运行值长、专工，专注机组启停事件物耗专项查询与分析。业务能力覆盖：单次启动/停机全流程水、煤、油、厂用电消耗查询；历史指定启停事件油耗明细查询；两次启停事件的耗时‑物耗横向对比分析；启动过程分阶段燃油消耗拆解分析。统计指标维度：水(t)、煤(t)、燃油(t)、启机厂用电(MWh)；支持输出总消耗量、分阶段明细消耗、阶段占比、同工况历史均值对比、跨事件差异率计算。业务口径：仅对**生产闭环启停事件**做统计计算；试验、调试、检修试转类事件直接过滤，不参与任何统计、展示。
   【主要业务场景】
   1. 查询本次启动事件水、煤、油、厂用电完整消耗；
   2. 查询本次停机事件水、煤、油、厂用电完整消耗；
   3. 查询指定历史启停事件的总油耗、分阶段油耗及启停耗时；
   4. 选取两条启停事件，完成耗时与全量物耗对比，计算各项差异率，定位差异突出阶段；
   5. 拆解单次启动各阶段燃油分布，定位高耗油阶段，识别燃油消耗异常点。

触发示例:
- 本次机组启动消耗了多少水、煤、油和厂用电？
- 本次停机消耗了多少水、煤、油和厂用电？
- 历史上这次冷态启动的油耗是多少？
- 把这两次启动的耗时和物耗对比一下。
- 本次启动哪个阶段最耗油？

- startStopDetails    # 查询某一次启停记录详情
- startStopStatic     # 统计指定时间范围内启动次数、停机次数，并补充累计运行时长、停机时长

## 触发条件
用户提问需要同时满足如下条件：
1. 业务领域限定：火电机组启停事件物耗相关查询；
2. 语义关键词：启动、停机、启停、物耗、水、煤、油、厂用电、油耗、阶段耗油、物耗对比；
3. 用户意图匹配上方5类业务场景；支持上下文代词「本次、这次、这两次」指代已提及的启停事件；
4. 排除场景：机组稳态日常运行能耗查询、检修物料消耗、试验调试能耗等非启停场景，不进入本Skill。

> 路由规则：单轮问句仅匹配**一个业务分支**，禁止多分支混合执行。

## 一、业务分支与路由规则
### 分支1：单次启动物耗查询
**触发问句**：
- 本次机组启动消耗了多少水、煤、油和厂用电？
- 本次停机消耗了多少水、煤、油和厂用电？

**处理逻辑**
1. 从对话上下文识别目标「本次启动」事件，提取机组标识、启停事件ID；若上下文无有效事件ID，返回兜底提示。
2. 先调用`startStopRecord`工具获取最近10次的启停记录根据问答取相关启动/停止 参数为 `nodeId` 前置skill的id取值 筛选出来第一条数据
2. 调用工具 `getStartStopTotalMaterial`，参数`resultId`为筛选出来数据的 result_id 获取该次启动总物耗、各阶段分项物耗、同工况启动历史均值数据。
3. 输出组装：
    - 输出水、煤、油、厂用电四项**总消耗量**；
    - 输出本次启动、停机各关键阶段的分项物耗明细；
    - 数据源存在历史均值时 需要对比本次和历史启动、停机各关键阶段的各分项物耗明细记录
    - 针对本次物料数据分析总结出结论
4. 边界校验：若启停事件状态为未闭环，增加提示文本：`本次启动尚未闭环，物耗数据不完整，仅供临时参考`。

### 分支2：历史启停记录油耗查询
- **触发问句**：
- 历史上这次冷态启动的油耗是多少？
- 历史上这次#2机组热态启动的油耗是多少？
- #2机组两次启动的耗时和物耗对比一下。
- 历史上这次#2机组启动哪个阶段最耗油

**处理逻辑**
1. 调用工具 `startStopStatic` 获取最新的一条启停记录 ，`startTime`参数和 `endTime` 参数不传
2. 调用工具 `startStopDetails`可以获取某一次启停记录详情 参数 `resultId` 取值为上一工具筛选出的结果的 `result_id`取值，可以获取关键阶段耗时
3. 调用工具 `getStartStopTotalMaterial`，参数`resultId`为筛选出来数据的 result_id 获取该次总燃油消耗量、关键阶段燃油消耗
4. 输出描述:
- 
3. 输出字段：启停工况类型、总燃油消耗量、关键阶段燃油消耗和关键阶段耗时统计；
   > 若部分阶段油耗字段采集缺失，则标注`无采集数据`，不做估算补全。

## 二、公共前置规则（全部分支共用）
1. **事件过滤规则**：自动剔除试验启停、调试冲转、检修试转事件，该类事件不参与统计、不对外输出。
2. **缺失数据处理**
   - 无同工况历史均值：明确标注`暂无同类型历史数据，无法对比`；
   - 单项字段采集为空：标注`无采集数据`；**严禁编造、估算任何缺失业务数值**。
3. **上下文代词支持**：代词「本次、这次、这两次」优先复用对话上下文已经识别出来的启停事件ID，用户无需重复输入机组、事件编号。
4. **输出字符约束**：输出文本**禁止携带ENSP、EMSP等文档隐藏标记**，仅输出纯业务文本。

## 三、兜底逻辑
1. 无法定位启停事件：`未能找到对应的启停记录，请确认启停事件，或补充事件相关信息。`
2. 启停事件未闭环：`该启停事件尚未闭环，物耗数据不全，结果仅作参考。`
3. 工具调用异常（数据源不可访问）：`启停物耗数据源暂不可访问，请稍后重试。`
4. 该事件无物耗采集：`该启停记录没有采集到物耗相关数据，无法进行查询。`

## 四、全局约束
1. 业务边界：仅处理2个指定业务意图，不扩展周期批量统计、异常事件批量筛选、全量历史列表等不在需求内的能力。
2. 计量单位规范：水(t)、煤(t)、油(t)；厂用电(MWh)；耗时(min)；百分比统一保留1位小数。
3. 分支隔离约束：单次用户问句只进入一个业务分支，禁止跨分支混合输出结果。
4. 安全输出：不输出数据库底层主键ID，对外统一输出业务事件ID。
