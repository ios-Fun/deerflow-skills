# 评估单处理效果

## 匹配问题
- 这条评估单处理后效果怎么样？
- 调完了有没有改善？
- 这条评估单 2026-29-08 处理后效果怎么样？

## 上下文规则
- 原评估单数据（`evaluationId`、目标、范围、因素、调整前数值）优先从上下文获取，**禁止重复调用** `getEvaluationByTagCode` 查询原单。
- 若上下文不存在原评估单数据，才要求用户指定，并调用 `getEvaluationByTagCode` 获取原单。
- 若用户指定了处理时间（如 2026-29-08），则调用 `getEvaluationByTagCode` 查询该处理时间**前后一天**的数据：
  - `startDate` = 处理时间 - 1 天
  - `endDate` = 处理时间 + 1 天
  - 传参 `tagCode`（指标编码），不传其他时间参数。
- 若用户未指定处理时间，回复：“请提供处理/调整时间，例如‘2026-29-08 处理后效果怎么样’。”

## 处理逻辑
1. 从上下文读取原评估单的目标指标、关键因素及调整前数值。
2. 根据用户指定的处理时间，查询该时间前后一天的数据，作为调整后数据。
3. 以处理时间为分界，对比调整前后目标指标及关键因素。
4. 说明：
   - 偏差是否收敛
   - 目标指标是否改善
   - 是否出现其他不利变化
5. 只能基于用户再次查询时的最新数据验证，不承诺后台持续跟踪。

## 输出模板

【处理/调整时间】...
【查询范围】处理时间前后一天（... 至 ...）

【目标指标】
- 调整前（上下文）：...
- 调整后（新查询）：...
- 变化：...

【关键因素】
- 因素1：调整前 ... → 调整后 ...
- 因素2：调整前 ... → 调整后 ...
- 因素3：调整前 ... → 调整后 ...

【偏差收敛情况】...
【是否出现其他不利变化】...
【结论】...

## 异常处理
- 若上下文缺失原评估单数据，回复：“未找到原评估单上下文，请提供评估单编号或重新查询。”
- 若用户未说明处理时间，回复：“请提供处理/调整时间，例如‘2026-29-08 处理后效果怎么样’。”
- 若无法获取处理时间前后一天的数据，回复：“无法获取指定处理时间前后的运行数据，请确认时间或数据范围。”
- 不得虚构调整前后的对比数据。
