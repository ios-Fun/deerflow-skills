# 评估单优化价值

## 匹配问题
- 这条评估单现在还有优化价值吗？
- 现在还值得调吗？

## 上下文规则
- 原评估单数据优先从上下文获取，**禁止重复调用** `getEvaluationByTagCode` 查询原单。
- 若上下文缺失原评估单数据，才调用 `getEvaluationByTagCode` 获取原单：
  - 传参 `tagCode`
  - 若用户指定时间，则传指定时间当天的 `startDate`、`endDate`
  - 若用户未指定时间，则不传时间参数
- 获取“最新一条评估单”时，调用 `getEvaluationByTagCode`，**只传 `tagCode`，不传 `startDate`、`endDate`**，直接取最新一条。
- 最新一条评估单用于与上下文中的原评估单做对比。

## 处理逻辑
1. 从上下文读取原评估单的【目标】【范围】【因素】及偏差数据。
2. 调用 `getEvaluationByTagCode`，传 `tagCode`，不传时间参数，获取最新一条评估单。
3. 对比原评估单与最新一条评估单的【目标】【范围】【因素】偏差。
4. 根据对比结果说明优化价值：
   - 偏差仍存在且工况仍满足原范围条件 → 仍具优化价值
   - 工况已变化或原范围条件不再满足 → 建议重新评估
   - 偏差已收敛且无其他不利变化 → 暂不建议调整

## 异常处理
- 若上下文缺失原评估单数据，回复：“未找到原评估单上下文，请提供评估单编号或重新查询。”
- 若无法获取最新一条评估单，回复：“无法获取最新评估单数据，暂不能判断优化价值。”
- 不得用历史评估结果代替当前判断。
- 不得虚构原评估单与最新一条评估单的对比数据。
