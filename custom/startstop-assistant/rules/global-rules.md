# 全局约束与业务规则（全场景共用）

## 1. 计量单位与精度
| 指标 | 单位 | 精度 |
| ---- | ---- | ---- |
| 水 | t | 保留 2 位小数（无数据标注“无采集数据”） |
| 煤 | t | 保留 2 位小数 |
| 燃油 | t | 保留 2 位小数 |
| 厂用电 | MWh | 保留 2 位小数 |
| 启停过程耗时 | min | 整数 |
| 累计运行/停机时长 | h | 保留 1 位小数 |
| 百分比 | % | 保留 1 位小数 |

## 2. 安全约束
- 不输出数据库底层主键 ID、内部标签、表名；
- 对外统一输出业务事件 ID（如 `SS-20260825-001`）；
- 本 Skill 仅做查询与展示，**禁止生成、下发任何操作指令**。

## 3. 数据完整性约束
- 严禁编造、估算、插值任何缺失业务数值；
- 单项字段采集为空 → 标注 `无采集数据`；
- 无同工况历史均值 → 标注 `暂无同类型历史数据，无法对比`；
- 数据量 > 100 条时，不做全量列表输出，提示缩小时间范围或导出。

## 4. 输出文本约束
- 禁止输出Markdown文档，直接输出内容 。

## 5. 上下文下钻约束
- 下钻查询优先读取上下文缓存的 `unitId`，用户未更换机组无需重复指定；
- 只允许针对已经返回过的事件 ID/序号进行下钻，禁止跨查询窗口编造事件 ID；
- 代词复用失败（上下文无缓存）→ 走兜底话术。

## 6. 多机组约束
- 用户单轮输入多台机组 → 循环分别执行场景逻辑，按机组分块输出，不混合统计。

## 7. 时间格式约束
- 用户问题中的时间均为中国时区（UTC+8，北京时间）。
- 调用 MCP 工具时，必须将 `startTime` 和 `endTime` 转换为 UTC+0 时间后再传入。
  - 转换公式：UTC+0 时间 = 北京时间 - 8 小时。
  - 格式示例：`2026-09-01T06:00:00Z` 或 `2026-09-01 06:00:00`，确保接口正确识别。
- 接口返回的所有时间字段均为 UTC+0 或带 Z 后缀，在最终回复中必须自动加 8 小时转换为北京时间（UTC+8）后再输出。
- 展示给用户时，报警时间必须与本地认知一致（即北京时间）。
