# 场景C：启停阶段识别

## 触发条件（同时满足）
- 业务领域：火电机组启停阶段相关查询；
- 语义指向“当前 / 进行中 / 现在 / 刚才”的状态；
- 意图关键词：机组阶段、启动阶段、停机阶段、冷态/温态/热态启动、并网还差哪些步骤、阶段切换时间、具备xxx条件、停止xxx。

## 分支路由

| 分支           | 覆盖问法                             | 优先级 |
|--------------|----------------------------------|-----|
| C1 启停阶段与步骤查询 | 当前启动/停机处于哪个阶段、并网前剩余步骤与条件、阶段切换时间点 | 1   |
| C2 启动类型判定    | 当前是冷态/温态/热态启动                    | 2   |
| C3 启动/停止条件判断 | 暖机阶段相关/盘车/停止条件相关                 | 3   |

> 两个分支优先级相同，互斥命中：仅出现“冷态/温态/热态 / 启动类型 / 启动模式”类关键词 → C2；其余阶段/步骤/切换时间类 → C1。

## 公共前置步骤
1. 调用 `match_for_best`，`match_type` 参数值传 `机组`，解析目标机组 `nodeId`（取返回结果中相似度最高的 `id`）。
2. 依据问句语义判断 `eventName`：
   - 启机相关（启动/冲转/并网/点火等）→ `启动`
   - 停机相关（停机/解列/惰走/熄火等）→ `停机`
3. 上下文代词「本次 / 现在 / 刚才」优先复用已识别的机组；若上下文已缓存机组且未更换，允许跳过 `match_for_best` 直接沿用。
4. 所有查询结果**仅用于信息展示**，禁止生成或下发任何操作指令。

## C1：启停阶段与步骤查询
**匹配问句示例**
- 现在 #2 机组启动到哪个阶段了？
- 查询 #2 机组并网前剩余步骤与条件
- 本次 #2 机组停机现在进行到哪个阶段？
- 刚才什么时候从锅炉点火阶段进入冲转准备阶段的？
- 刚才#2机组什么时候从供热解除阶段进入机组 AGC 退出阶段的？
- 现在#2机组具备锅炉点火条件吗？

**工作步骤**
1. 执行公共前置步骤，得到 `nodeId` 与 `eventName`。
2. 调用 `stageRecord`：
   - `nodeId` = 前置步骤返回的 `id`
   - `eventName` = `启动` 或 `停机`
   获取当前阶段信息、已完成阶段清单、阶段切换时间线。
3. 依据问句子意图组装输出：
   - **子意图 a｜当前所处阶段**：当前阶段名称、阶段开始时间、本阶段已持续时长、本阶段主要完成项、下一阶段目标。
   - **子意图 b｜并网前剩余步骤与条件**：当前阶段下尚未完成的关键步骤与必须满足的条件；只展示信息，不直接下达操作指令。
   - **子意图 c｜阶段切换时间点**：切换时间、切换前阶段、切换后阶段、对应关键事件时间点。
4. 边界校验：
   - 无正在进行的启停事件 → 兜底 F8；
   - 阶段时序数据缺失 → 兜底 F9；
   - 找不到用户指定的阶段切换记录 → 兜底 F10。

## C2：启动类型判定
**匹配问句示例**
- 当前 #2 机组冷态启动、温态启动还是热态启动？

**工作步骤**
1. 执行公共前置步骤，得到 `nodeId`；`eventName` 固定为 `启动`。
2. 调用 `stageRecord`：
   - `nodeId` = 前置步骤返回的 `id`
   - `eventName` = `启动`
   取返回结果第一层级下 `startDatas` 节点。
3. 从 `startDatas` 中读取：
   - `currentStartMode`：启动模式
   - `currentStartModeDesc`：判定依据描述
4. 组装输出：
   - 启动类型：冷态 / 温态 / 热态（按 `currentStartMode` 映射）；
   - 判定依据：直接输出 `currentStartModeDesc` 内容；
   - 若字段缺失 → 标注 `无采集数据`，不编造判定。
5. 无正在进行启动事件 → 兜底 F8。

## C3：启动/停止条件判断
**匹配问句示例**
- #2机组点火后还需要暖机多久才允许升负荷？
- #2机组暖机阶段哪些条件还没有满足？
- #2机组刚打闸停机，什么时候可以停止盘车？
- #2机组现在能退出连续盘车吗？
- #2机组可以停止循环水系统吗？

**工作步骤**
1. 执行公共前置步骤，得到 `nodeId`；`eventName` 固定为 `启动`。
2. 调用工具 `stageRecord`：
   - `nodeId` = 前置步骤返回的 `id`
   - `eventName` = `启动` 或 `停机` (盘车相关问题传`停机`)
   获取当前启动阶段信息
3. 调用工具 `startStopCondition`:
   - `condition` =  暖机相关问题参数传`暖机` , 停止盘车相关问题参数传`盘车`，循环水系统相关问题参数传`循环水系统`
   - `nodeId` = `stageRecord` 工具返回的第一层节点的 `id`
   获取核心参数判断是否满足暖机/盘车/等其他要求
4. 依据问句子意图组装输出：
   - **子意图 a｜还需要暖机多久**：核查核心参数，结合规程条件估算剩余暖机时间，并说明当前是否满足升负荷条件。
   - **子意图 b｜暖机阶段哪些条件还没有满足**：按暖机结束条件逐项展示当前值、标准值和判断结果，重点列出未满足条件及预计改善方向。
   - **子意图 c｜停止条件判定**：判断是否具备停止条件、是否可以中断
5. 无正在进行启动事件 → 兜底 F8。


## 兜底
| 异常场景 | 文案编号 |
| ---- | ---- |
| 无正在进行的启停事件 | F8 |
| 阶段时序数据缺失 | F9 |
| 找不到指定阶段切换记录 | F10 |
| 机组实体无法识别（`match_for_best` 无有效返回） | F2 |

## 全局约束
1. 业务边界：只处理 C1、C2 两个业务分支；不做物耗计算、参数趋势分析、操作指令下发。
2. 分支隔离：单轮问句只能走一个业务分支，不能跨分支混合输出。
