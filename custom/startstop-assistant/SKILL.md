# 火电机组启停统一 Skill

## 0. 加载顺序（每次调用必执行）
1. `rules/global-rules.md`      —— 全局约束
2. `rules/data-filter-rules.md` —— 数据过滤与业务口径
3. `rules/fallback-messages.md` —— 兜底话术
4. 依据 §2 路由结果，加载 `scenarios/` 下**唯一一个**场景文件

> 约束：单轮问句只允许加载一个场景文件，禁止跨场景混合输出。

## 1. 门禁检查（Must Pass，先于路由）

| 编号 | 门禁条件 | 不通过动作 |
| ---- | ---- | ---- |
| P1 | 业务领域为火电机组启停 | 退出本 Skill |
| P2 | 事件类型为生产闭环启停（非试验/调试/检修试转） | 按 data-filter-rules 过滤；全部被过滤则走兜底 |
| P3 | 意图落在 A/B/C 三大场景范围内 | 退出本 Skill |

## 2. 场景路由（优先级从高到低，命中即停）

### Route-C → `scenarios/stage-identify.md`
**命中条件（同时满足）**
- 语义指向“当前 / 进行中 / 现在 / 刚才”的状态识别；
- 关键词命中任一：当前阶段、启动到哪个阶段、停机到哪个阶段、并网还差、阶段切换时间、现在是什么启动类型、冷态/温态/热态判定、具备条件。

### Route-A → `scenarios/material-query.md`
**命中条件**
- 关键词命中任一物耗指标：水、煤、油、厂用电、物耗、油耗、耗油、消耗量、阶段耗油；
- 或含物耗对比 / 差异率 / 占比语义（如“这两次对比一下”且上下文有物耗）。

### Route-B → `scenarios/record-stats.md`
**命中条件**
- 关键词命中次数/时长/记录/列表/详情/分类统计：启停了多少次、停机时长、启停记录、列出最近N次、最近一次详情、冷/温/热态分类统计、非计划启停。

### 2.1 冲突消解规则
1. **显式物耗指标 > 阶段状态语义**：问句中出现具体物耗指标（水/煤/油/厂用电/物耗/油耗）时，即使含“当前/阶段”字样，一律路由 Route-A。
   例：“本次启动哪个阶段最耗油？” → Route-A。
2. **“当前 / 进行中 / 刚才 / 现在” + 阶段或状态语义，且无物耗指标** → Route-C。
   例：“现在启动到哪了？” → Route-C。
3. **“最近一次 + 详情/什么时候”且无物耗指标** → Route-B。
   例：“最近一次#1机组是什么时候启动的？” → Route-B。
4. **“最近一次 + 物耗指标”** → Route-A。
   例：“本次启动消耗多少水煤油？” → Route-A。
5. **“冷态/温态/热态”判定类问句**：
   - 含“当前 / 本次 / 现在” → Route-C（分支 C2）；
   - 含“历史上 / 去年 / 上个月”等历史时间 → Route-B（分类统计）。

## 3. 上下文与多轮
- 代词「本次 / 这次 / 现在 / 刚才 / 这两次」优先复用对话上下文中已识别的 `unitId` 与启停事件 `result_id`；
- 跨场景下钻时（如从 B3 跳 A），允许复用已缓存的事件 ID，但仍只加载目标场景文件；
- 上下文缓存的字段：`unitId`、`timeRange`、`eventIndexMap`（业务事件ID ↔ result_id）。

## 4. 输出总则
1. 只输出业务文本，禁止 ENSP/EMSP 等隐藏字符；
2. 严格遵循 `rules/global-rules.md` 的单位与精度规范；
3. 数据质量提示、边界说明、交互指引按各场景文件规范拼装；
4. 不输出数据库底层主键，只输出业务事件 ID。
