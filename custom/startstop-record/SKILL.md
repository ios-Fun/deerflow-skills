## 触发条件
当用户查询同时满足以下特征时触发本 Skill：
1. 查询主体为指定机组（如 #1机组、#2机、1号机组），支持多机组单轮查询（多机组时循环执行单机组逻辑）；
2. 核心诉求包含启停次数、停机时长、启动时间、启停记录、启停分类、非计划启停、启动性能、启停复盘等语义；
3. 时间范围支持：本年度、今年、本季度、本月、最近N天、最近N次、自定义起止时间段；
4. 排除：单纯设备参数、性能寻优、检修计划类问句，不进入本Skill。

> 路由优先级：**机组实体识别 > 时间解析 > 业务语义关键词匹配**；单轮问句仅进入1个业务分支；若同时命中多个分支关键词，取优先级最高分支，不做多分支混合执行。
> 分支优先级排序：最近一次详情 > N次记录列表 > 停机时长统计 > 分状态分类统计 > 总次数统计。


## 一、业务分支与路由规则

### 分支1：启停总次数统计
- **触发关键词**：启停了多少次、启停总次数、累计启停次数、启停次数统计、一共启停多少次
  - **分支优先级**：5（最低）

**典型问句**
- 本年度#1机组启停了多少次？
- #2机组今年一共启停多少次？
- 上半年#1机启动加停机总共多少次？
- 近三个月#1机组累计启停多少次？

**处理逻辑**
1. 实体解析：识别`nodeId` 取自全局前置规范匹配相似度最高返回结果中的 `id` 值 ，解析`timeRange`；未识别时间，默认取当年自然年；时间格式非法返回提示，不继续统计。
2. 调用工具 `startStopStatic` 可以获取到启动次数、停机次数和各种完成启停时间范围,通过启停时间范围需要自己计算出累计运行时长、累计停机时长并回答下列相关问题
3. 数据集过滤：执行公共前置过滤，剔除试验、调试、脏数据。
4. 指标统计：
    - 统计周期内**有效启动总次数**、**有效停机总次数**；
    - 计算机组累计运行时长、累计停机时长；
    - 计算启停事件闭环率：闭环事件数 / 全部生产事件数（用于数据质量提示）。
5. 事件索引构建：为过滤后每一笔启停事件生成业务索引ID，用于后续上下文下钻。
6. 周期边界校验：
    - 若周期结束时刻机组处于**运行未闭环**：停机事件未完成，不计入停机统计，输出边界说明；
    - 若周期结束时刻机组处于**停机未闭环**：本次停机时长仅统计至查询时刻，标注为“进行中停机”。
7. 数据质量校验：当事件闭环率＜80%，增加数据质量提示，告知用户部分事件未闭环，统计结果存在偏差。

**输出示例**
>【统计范围】2025-01-01 ~ 2025-12-31
>【统计对象】#2机组（DC3R0102，节点ID 415027）
>【数据口径】原始台账40条 → 剔除3条重复补录（02-09启动、03-19启动、08-11启动各重录1条，起始/结束时间完全相同）→ 有效事件37条
>【启停统计】
> - 有效启动总次数：17次
> - 有效停机总次数：20次
> - 事件闭环率：100%（37/37条记录首尾时间完整）
>【周期累计指标】
> - 累计运行时长：xxx h
> - 累计停机时长：xxx h
>【边界说明】统计截至xxxx，当前机组处于xx状态。支持基于事件索引ID，查询任意一次启停完整详情。


### 分支2：启停次数分状态分类统计
- **触发关键词**：启动多少次、停机多少次、冷态启动、温态启动、热态启动、启停分类、各类启动占比
- **分支优先级**：4

**典型问句**
- 今年#2机组启动了多少次、停机了多少次？
- #2机本年度冷态/温态/热态启动各有多少次？
- #2机热态启动占比多少？
- 去年#2机组各类启动分别多少次？

**处理逻辑**
1. 实体解析：识别机组、时间范围；执行公共数据过滤。
2. 调用工具 `startStopStatic` 可以获取到启动次数、停机次数、冷态/温态/热态
2. 基础总量输出：输出周期内启动总次数、停机总次数。
3. 启动事件分类统计（依据机组缸温/停机冷却时间判定的启动类型标签）：
    - 冷态启动、温态启动、热态启动分别计数，计算各类启动占全部启动事件的百分比，保留1位小数；
4. 标签完整性分支处理：
    - ✅全部事件带启动类型标签：输出完整分类统计；
    - ⚠️部分事件缺失标签：输出可统计部分，明确标注缺失标签事件数量；
    - ❌全部无标签：仅输出启动总次数，提示“暂无启动类型分类标签，无法做冷/温/热态拆分”。
5. 停机事件：默认不拆分；当用户明确追问停机原因分类（计划/非计划/故障/检修），追加停机分类统计。
6. 附加辅助指标：输出非计划启动次数（若数据源存在该标签）。

**输出示例**

> 【统计范围】 2026‑01‑01 ~ 2026‑09‑10
> 【统计对象】 #1机组
> 【启停总量】
> - 有效启动：8次
> - 有效停机：7次
> - 非计划启动：1次

| 启动类型 | 次数 | 占全部启动占比 |
| -------- | ---- | -------------- |
| 冷态启动 | 2次 | 25.0% |
| 温态启动 | 3次 | 37.5% |
| 热态启动 | 3次 | 37.5% |

> 【数据质量说明】
> 本次统计8笔启动事件全部携带启动类型标签，无缺失。

### 分支3：最近一次启动详情查询
- **触发关键词**：最近一次启动、什么时候启动的、最新启动时间、上次启动详情、上一次启动情况
- **分支优先级**：1（最高）

**典型问句**
- 最近一次#1机组是什么时候启动的？
- #2机上次启动的并网时间和耗时是多少？
- #1机最新一次启动成功了吗？
- #1机组上一次启动过程关键节点。
- #2机组某一次启动详情

**处理逻辑**
1. 实体解析：识别目标机组，时间默认取全量历史，支持用户限定时间范围。
2. 调用工具 `startStopStatic` 可以获取启停全流程关键业务字段
3. 过滤数据集，筛选启动类事件，按**启动开始时刻倒序**取第一条事件。
4. 调用工具 `startStopDetails`可以获取某一次启停记录详情 参数 `resultId` 取值为上一工具筛选出的结果的 `result_id`取值，若是筛选多个结果可以一次调用合并结果分析 ，这里面包含了此次启停的所有过程事件，根据返回结果具体分析
5. 调用工具 `getStartStopTotalMaterial` 可以获取启停物耗相关信息，`resultId` 参数为上一步工具返回结果 `result_id`
6. 提取启停全流程关键业务字段：
    - 启动开始时间：`YYYY‑MM‑DD HH:mm`；
    - 启动类型：冷态 / 温态 / 热态 / 未分类；
    - 锅炉点火时间、汽轮机冲转时间、机组并网时间；
    - 启动总耗时（点火至并网，单位min，整数）；
    - 机组带满负荷时间；
    - 启动最终状态：成功 / 异常中断 / 启动失败 / 启动进行中；
    - 事件ID、是否为非计划启动取值为 `result_id`；
    - 异常标记：存在异常则输出异常简述；无异常填“无”。
7. 实时状态判断：若事件为进行中，明确提示为中间快照，结果以事件闭环后为准。
8. 兜底：无匹配启动事件输出兜底话术。

**输出示例**

> 【查询对象】#1机组｜最近一次启动事件
> - 事件ID：SS‑20260825‑001
> - 启动开始时间：2026‑08‑25 08:12
> - 启动类型：热态启动
> - 锅炉点火时间：2026‑08‑25 08:12
> - 汽轮机冲转时间：2026‑08‑25 08:36
> - 机组并网时间：2026‑08‑25 09:05
> - 点火至并网总耗时：53 min
> - 带满负荷时间：2026‑08‑25 10:21
> - 是否非计划启动：否
> - 启动最终状态：成功
> - 过程异常标记：无

### 分支4：最近N次启停记录列表查询
- **触发关键词**：最近X次启停记录、启停记录列表、历史启停记录、启停明细、列出最近N次启停
- **分支优先级**：2

**典型问句**
- 帮我看一下#2机组最近5次启停记录。
- #2机最近10次启停的物耗和异常情况。
- 列出#1机本月所有启停记录。

**处理逻辑**
1. 调用工具 `startStopStatic` 可以获取启停全流程关键业务字段
2. 调用工具 `getStartStopTotalMaterial` 可以获取启停物耗相关信息，`resultId` 参数为上一步工具返回结果 `result_id`
3. 公共过滤，全部启停事件按**事件完成时间倒序**，截取前N条；事件未完成的放在列表顶部并标记“进行中”。
4. 每条记录提取标准化字段：序号、事件ID、启停时间、启停类型、全过程耗时、物耗指标（启动燃油消耗、启机厂用电量）、事件性质（计划/非计划）、异常标记。
上下文支撑：每条记录携带事件ID，支持用户后续输入“查看第3次详情”、“查看事件SS‑xxxx详情”直接下钻，不需要重复输入机组。
6. 当有效事件小于请求N，输出实际条数，并提示“仅查询到X条有效启停事件”。

**输出示例**

> 【查询对象】#1机组｜最近5次启停记录

| 序号 | 启停时间         | 启停类型   | 全过程耗时 | 物耗指标    | 异常情况     |
| ---- | ---------------- | ---------- | ---------- | ----------- | ------------ |
| 1    | 2026-08-25 09:05 | 热态启动   | 53 min     | 燃油12.65 t | 无           |
| 2    | 2026-08-20 22:10 | 计划停机   | 28 min     | -           | 无           |
| 3    | 2026-08-15 10:33 | 温态启动   | 62 min     | 燃油18.20 t | 辅机小幅扰动 |
| 4    | 2026-08-10 18:05 | 非计划停机 | 16 min     | -           | 无           |
| 5    | 2026-08-05 07:42 | 冷态启动   | 125 min    | 燃油45.72 t | 无           |


> 【交互指引】
> 可输入：查看第N次详情 / 查看事件ID:XXX详情，进行单事件深度复盘。

### 分支5：停机总时长统计
- **触发关键词**：停了多长时间、停机总时长、累计停机时间、停机时长分类、计划停机多久、故障停机时长
- **分支优先级**：3

**典型问句**
- 今年#1机组总共停了多长时间？
- #2机本年度计划停机和非计划停机各多久？
- #1机故障停机累计多少小时？

**处理逻辑**
1. 解析机组、时间范围，执行公共过滤。
2. 停机时长统计规则：
    - 闭环停机事件：停机开始时刻到停机结束时刻差值；
    - 进行中停机事件：停机开始时刻至查询当前时刻，单独标记，不参与占比计算；
3. 分类维度：计划停机、非计划停机、故障停机、检修停机；
4. 计算各类停机时长、占**闭环停机总时长**百分比（进行中停机不参与占比分母）；
5. 附加指标：非计划停机累计时长、非计划停机占比，供可靠性分析；
6. 数据提示：部分停机事件缺失停机原因标签时，输出“未分类停机”项，统计对应时长。

**输出示例**

> 【统计范围】2026‑01‑01 ~ 2026‑09‑10
> 【统计对象】#1机组
> 【停机统计】
> - 闭环停机总时长：186.2 h（约7天18小时）
> - 进行中停机时长：0 h

| 停机类型 | 时长(h) | 占闭环停机时长占比 |
| -------- | ------- | ------------------ |
| 计划停机 | 122.5 | 65.8% |
| 非计划停机 | 26.7 | 14.3% |
| 故障停机 | 12.0 | 6.4% |
| 检修停机 | 25.0 | 13.4% |

> 【说明】
> 本周期无进行中停机事件；全部停机事件均携带停机原因标签。

## 二、统一执行流程
### 步骤1：意图识别与分支路由
1. NLP实体抽取：提取`unitId`机组编号、时间表达式、数值N、业务关键词；
2. 时间解析：自然语言时间转为标准`[startTime,endTime]`；时间解析失败返回友好提示，终止Skill；
3. 根据关键词+优先级，路由至唯一业务分支。

### 步骤2：公共数据过滤（全分支前置）
1. 强制剔除事件类型：调试启停、试验冲转、检修试转、程控联动试验、大修后空转试验；
2. 剔除脏数据：启停开始/结束时间为空、事件动作类型为空的记录；
3. 标记：跨时间窗口未闭环事件，保留但不纳入闭环统计，输出专门边界说明；
4. 输出数据集质量元信息：事件总数、过滤丢弃数量、有效事件数量，供内部逻辑判断，按需对外提示。

### 步骤3：分支专属业务处理
执行对应分支统计、分类、计算逻辑，生成中间结果。   

### 步骤4：结果组装与渲染
1. 按照分支输出规范组装Markdown文本；
2. 附加边界说明、数据质量提示、交互指引；
3. 上下文记忆：保存本次查询`unitId`、`timeRange`、事件索引映射，用于后续下钻对话。

## 三、兜底逻辑
1. 时间解析失败：
> 无法识别你输入的时间范围，请调整时间描述，例如“2026年1‑6月”、“本年度”。

2. 过滤完成后，周期内无有效生产启停事件：
> 当前查询周期内未查询到#X机组有效生产启停记录，请确认机组编号或调整时间范围后重试。

3. 工具调用异常（数据源不可用）：
> 启停事件数据源暂不可访问，请稍后重试。

## 四、全局约束与业务规则
1. **输出边界**：
2. **数据处理约束**
    - 试验、调试类事件一律过滤，不参与统计，不对外展示；
    - 缺失标签数据不得编造、不得估算，必须明确标注缺失情况；
    - 时间精度统一到分钟；时长单位优先小时(h)，启机过程耗时单位分钟(min)；百分比保留1位小数。
3. **上下文下钻约束**
    - 用户下钻查询事件详情，优先读取上下文缓存的`unitId`，用户未更换机组无需重复指定；
    - 下钻只针对已经返回的事件ID/序号，不支持跨查询窗口随意编造事件ID。
4. **多机组约束**
    - 用户输入多台机组，循环分别执行Skill逻辑，分机组输出统计结果；
5. **安全约束**
    - 不输出原始数据库主键ID，对外输出业务事件ID；
    - 数据量过大（>100条），不全部列表输出，提示缩小时间范围或使用导出。
6. **分支隔离约束**：一个问句只进入一个分支，禁止多分支同时执行。
