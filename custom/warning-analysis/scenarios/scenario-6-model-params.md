# 场景6：模型测点参数、工况变化问题

## 适用问题

- 哪些模型参数一起变了？
- 模型关联参数变化
- 模型测点变化
- 需要结合模型信息分析工况变化

## 允许工具

- `get_tag_statistic_data`
- `get_tag_values`
- `get_model_info`
- `get_alarm_list`

## 执行步骤

1. 确认目标测点ID（或从已有 alarmList 中获取）。
2. 对目标测点调用 `get_tag_statistic_data` 和 `get_tag_values`，确定异常时间窗口及实际值/预估值/严重度的变化形态。
3. 对目标测点ID调用 `get_model_info`，获取测点所在模型信息：
   - 返回中 `data` 下的 `id` 为模型ID，`id` 下面的内容为测点编码。
   - 将测点编码按模型ID分别存入 `modelTagCodes_modelId`。
4. 对每个模型ID下的测点编码列表，结合询问时间段（start_time 与 end_time，中国时区）调用 `get_alarm_list`，查询该模型下同时段的报警。
5. 筛选出在目标测点异常时间窗口内也触发了报警的测点。
6. 对筛选出的测点通过tagId调用 `get_tag_statistic_data`，对比其趋势是否与目标测点同步偏离。
7. 综合判断：
   - **实际值**：是否明显升高/降低；是否持续变化；是否存在突变；是否与历史正常状态存在明显差异。
   - **模型预估值**：是否随工况变化；是否持续变化；是否存在明显变化区间。
   - **关联工况**：判断异常主要属于：
     - 实际值变化；
     - 工况变化导致预估值变化；
     - 实际值和预估值共同变化。

## 输出要求

- 先给出结论：本次共有 X 个模型参数同步变化（或未发现同步变化）。
- 对每个同步变化的参数给出：测点名称、实际值、预估值、偏差幅度、持续时间。
- 注明判断依据（基于趋势对比）。
- 必须展示趋势图（调用了 `get_tag_values`）。
- 不能在缺少关联工况数据时直接判断具体原因。没有对应数据时不得直接推断原因。
