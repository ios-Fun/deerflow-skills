# 时区转换规则

- 用户问题中的时间均为中国时区（UTC+8，北京时间）。
- 调用 MCP 工具时，必须将 `startTime` 和 `endTime` 转换为 UTC+0 时间后再传入。
  - 转换公式：UTC+0 时间 = 北京时间 - 8 小时。
  - 格式示例：`2026-09-01T06:00:00Z` 或 `2026-09-01 06:00:00`，确保接口正确识别。
- 接口返回的所有时间字段均为 UTC+0 或带 Z 后缀，在最终回复中必须自动加 8 小时转换为北京时间（UTC+8）后再输出。
- 展示给用户时，报警时间必须与本地认知一致（即北京时间）。

# 空数据处理规则

- 如果 `alarmList` 为空（即当前时间范围内无有效预警），则**必须立即结束分析**，回复用户：
  > 当前时间段内未发现有效预警，暂无明显异常。
- 不得继续调用 `get_tag_statistic_data`、`get_tag_values`、`search_tags` 等其他工具，也不得进行任何推断。
- 对于统计类问题，若 `alarmListStatistic` 为空，同样直接回复“未查询到相关历史预警记录”。

# 工具调用全局约束

- 每个分析场景只允许调用该场景文件中“调用对应 MCP 工具”小节显式列出的工具，未列出的工具一律禁止调用。
- 禁止因“想进一步确认”而额外查询未触发报警的测点、未涉及的设备或非指定的时间段。
- 若当前场景所需数据已获取（如 `alarmList`），禁止重复调用工具获取相同数据。
- 工具调用应尽量并发执行，减少不必要的串行等待。
- 除场景明确允许外，不得调用 `search_tags`、`get_model_info` 等额外工具。
